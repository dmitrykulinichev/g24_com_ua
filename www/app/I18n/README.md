# Мови лендінгу (app/I18n)

Українська — основна, на корені адреси (`/features`); інші мови — з префіксом (`/en/features`, `/ru/features`).
План і стан — `workspace/plans/landing-i18n-plan.md`.

## Як влаштовано

| Що | Де | Відповідальність |
|---|---|---|
| Мови, основна, відкриті, перекладені адреси | `config/i18n.php`, `LocaleConfig` | лише конфіг |
| Мова запиту з адреси | `LocaleResolver` (у `index.php`, до маршрутизації) | знімає префікс — маршрути й контролери одні для всіх мов; `/uk/…` → 301; закрита мова → 404; `/api/…` — мова з `X-Locale` |
| Мова й адреса поточної сторінки | `Locale` | стан запиту |
| Тексти | `lang/{uk,en,ru}.php`, `Translator` | ключ через крапку, `:плейсхолдери`; немає перекладу → українська; немає й там → ключ |
| Адреси з мовою | `LocalizedUrl` | `to()`, `canonical()`, `alternates()` (hreflang, перемикач, мапа сайту) |
| Скріни трьома мовами | `content/screens.json`, `app/Screens/ScreenRegistry`, `views/partials/screen.blade.php` | реєстр скрінів; файл мовою сторінки, не знято — українська; alt — `lang/*.php` → `screens.<id>`; мапа сайту бере звідси картинки сторінок |
| Помічники в Blade | `helpers.php` | `t()`, `t_list()`, `t_json()`, `lurl()`, `locale()` |

## Правила

- Внутрішнє посилання — завжди `lurl('/pricing')`, не `/pricing`: інакше з англійської сторінки перекине на українську.
- Текст на сторінці — `t('ключ')`; ключ спершу в `lang/uk.php` (основа), потім переклади.
- Запит до `/api` з JS — `apiFetch()` (передає мову сторінки в `X-Locale`); лендінг пересилає її в СААС (`SpaApiService`).
- **Відкрити мову** відвідувачам — `LANDING_LOCALES=uk,en,ru` у `.env`. Закриту видно лише з `LANDING_LOCALES_PREVIEW=true`.
- **Перекладена сторінка** — додати її адресу в `localized_paths` (`config/i18n.php`): лише тоді canonical поточною
  мовою, hreflang і мовні адреси в мапі сайту. Неперекладена під `/en` показує український текст з canonical на
  українську адресу — без дублів для пошуковиків.

## Скріни

- Скрін на сторінці — лише `@include('partials.screen', ['id' => '…'])` (перший екран — ще `'eager' => true`), без прямих шляхів: тест не пропустить.
- Новий скрін: запис у `content/screens.json` (звідки й за яким сценарієм знімати, на яких сторінках) → файл
  `assets/img/screens/uk/<id>.webp` → підпис `screens.<id>` у всіх трьох `lang/*.php`.
- Інша мова — той самий `<id>.webp` у `assets/img/screens/en|ru/`. Нічого більше міняти не треба: сторінка й мапа сайту
  підхоплять самі; `?v=` в адресі оновить кеш після перезнімання.
- Знімати й складати — `tools/screens/capture.mjs` (поруч з `www/`, на сервер не йде), за тим самим реєстром:
  `app <кадр> --locale en` (кадр з Android-емулятора, мову застосунку перемкнути в його налаштуваннях),
  `compose` (кадри → рамка телефона → webp), `cabinet [id]` (вебкабінет усіма мовами одразу; раз — `login`),
  `status`. Сирі кадри застосунку — `tools/screens/src/<мова>/` (у git): перескласти можна без перезнімання.
  Усі мови — за один захід, щоб у кадрі були ті самі дані.
- Особисті дані на скрінах: кабінет знімаємо з демо-парку «Київ» (id 15, дані вигадані). Назви інших парків
  акаунта знімання (перемикач парків, фільтр графіка) скрипт розмиває сам — список у `cabinet_blur_text`
  (`content/screens.json`); з'явився ще парк — дописати туди. Сторінки зі справжніми email чи телефонами
  персоналу (напр. «Команда») на лендінг не ставимо.
- Скріни документації (`assets/img/docs/`, `SCREENSHOTS_CATALOG.md`) — окремо, поки лише українською.

## Деплой

Після заливки змінених шаблонів (`views/`) по FTP — очистити `storage/cache/`: скомпільовані шаблони Blade можуть
лишитися старими (FTP зберігає дату файлу, старшу за скомпільовану копію). Перекомпілюються самі.

## Тести

`docker compose exec -T php php /var/www/landing/tests/run.php` (з кореня `park`).
